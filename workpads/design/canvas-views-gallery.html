Recommendation

The gallery's real finding is restraint: five of the six "views" are not separate canvas modes. argus needs one signature canvas — the DAG (Progress) — which already answers structure and liveness in a single read, plus a small amount of chrome and, later, one genuinely additive renderer.

Ship: keep the DAG / Progress as the default for every run (running runs already route here and paint live state); add a thin always-present NOW status strip (N running · M failed · elapsed) — that's the entire useful payload of "Activity" without a 4th mode. Later (gated): a Timeline/Gantt as a 2nd renderer over the same RunModel for the duration/critical-path question; a Table panel for at-scale scanning. Never as modes: Activity (→ chrome strip), Swimlane (→ the DAG/Timeline row axis), Digest (→ a summary line in RunOverviewPanel — which also answers the open "human-readable objective + what data it ran on" request).

Net: 3 shipped canvas views unchanged · 1 NOW strip · +1 Timeline later — zero combinatorial mode-state. The full reasoning + phased plan is in workpads/design/navigation-and-views-plan.md.
